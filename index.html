A better path_helper. Your paths, in the order you actually asked for.

You would never hard-code a string in your program, yet your PATH is probably one long hard-coded line in a dotfile. This is a replacement for Apple's /usr/libexec/path_helper that keeps the good parts and fixes the rest. Available in Ruby and Crystal, and it runs on any unix-like system.

01 / WHAT IT DOES

Four things Apple left out

Per-user paths

Your paths, ordered ahead of the system's. No sudo, no editing files that belong to every account on the machine.

More than PATH

Man pages, C includes, pkg-config and the dyld library and framework paths, all managed with the same pattern.

Debuggable

Ask it where a path came from and it tells you, file by file, duplicates marked.

No side effects

It prints a string. You decide what to do with it. Nothing is eval'd behind your back.

02 / WHY IT EXISTS

Apple puts the system first. Always.

Apple's helper reads /etc/paths first and everything from /etc/paths.d/ afterwards, so the system directories land at the front of your PATH:

$ /usr/libexec/path_helper
PATH="/usr/local/bin:/usr/local/sbin:/usr/bin:/usr/sbin:/bin:/sbin:/usr/local/go/bin:<snip>

Want the current OpenSSL you installed with MacPorts to win? Want your newer LLVM from pkgsrc to be found first? Apple says too bad. And that is only the ordering. The rest:

  • Everything lives in /etc, so adding or removing a path segment needs elevated permissions.
  • Being in /etc also makes every change system-wide, whether you wanted that or not.
  • It handles PATH and MANPATH only, while development and administration need headers, libraries and pkg-config just as often.
  • The string it returns is designed to be eval'd. eval is not always evil, but returning a plain string and letting you assign it is simpler and harder to get wrong.
03 / INSTALL

Clone it, or grab a release

Clone the repository, or download a prebuilt Crystal binary from the Releases page. The Ruby version is a single script with no dependencies beyond Ruby itself, so there is nothing to build; the Crystal version compiles to a binary with shards build. It does not need to live in /usr/local/bin or anywhere special.

  1. Clone the repository, or download a build from Releases.
  2. Make sure it is executable: chmod +x path_helper
  3. Read the help, because you are the sort of person who reads instructions: path_helper -h
  4. Run the setup and let it create the directories and files for you.
  5. Paste the snippet setup prints into your ~/.zprofile or ~/.bash_profile.
# Mac, per-user paths under ~/Library, nothing touched in /etc
path_helper --setup --no-config --no-etc

# Linux, or if you prefer per-user paths under ~/.config/paths
path_helper --setup --no-lib --no-etc

Note the --lib and --config switches and their --no- counterparts. Apple's helper stays where it is in /usr/libexec, untouched, so you can always go back.

04 / USAGE

Ask for a path, get a path

It will not set your PATH. It returns one, and you set it:

$ PATH=$(path_helper -p)
$ export PATH

Keeping what is already there

With no argument you get a completely fresh PATH, built only from your files. Pass it the current path, or any path you want kept, and that is appended after the generated one, with anything already in it left out. The other switches take an argument in the same way.

$ export PATH=$(path_helper -p "$PATH")

In your shell startup

This is what --setup prints for you at the end, here for the Ruby script installed in ~/bin (the Crystal build prints the same lines without the leading ruby). Drop it in ~/.zprofile or ~/.bash_profile:

# Put this in your ~/.bash_profile or your ~/.zprofile
if [ -x '/Users/you/bin/path_helper' ]; then
  export C_INCLUDE_PATH=$(ruby '/Users/you/bin/path_helper' -c)
  export DYLD_FALLBACK_FRAMEWORK_PATH=$(ruby '/Users/you/bin/path_helper' --dyld-fallback-fram)
  export DYLD_FALLBACK_LIBRARY_PATH=$(ruby '/Users/you/bin/path_helper' --dyld-fallback-lib)
  export DYLD_FRAMEWORK_PATH=$(ruby '/Users/you/bin/path_helper' --dyld-fram)
  export DYLD_LIBRARY_PATH=$(ruby '/Users/you/bin/path_helper' --dyld-lib)
  export MANPATH=$(ruby '/Users/you/bin/path_helper' -m)
  export PKG_CONFIG_PATH=$(ruby '/Users/you/bin/path_helper' --pc)
  export PATH=$(ruby '/Users/you/bin/path_helper' -p)
fi

05 / CONFIGURATION

One path per line, in a file, in order

A path file is a list of directories, one per line. The order inside the file matters, and so does the order the files are read in, which is why numeric prefixes are worth the two seconds they cost.

$ tree ~/.config/paths
~/.config/paths
├── paths
└── paths.d
    ├── 05-pkgsrc
    ├── 08-homebrew
    ├── 60-Crystal
    ├── 62-Haskell
    └── 65-Rust

$ cat ~/.config/paths/paths.d/05-pkgsrc
/opt/pkg/bin
/opt/pkg/sbin

Search order

Files are read in this order, and anything missing is skipped. Your directories come first, which is the whole point:

  1. ~/Library/Paths/paths.d
  2. ~/Library/Paths/paths
  3. ~/.config/paths/paths.d
  4. ~/.config/paths/paths
  5. /etc/paths.d
  6. /etc/paths

Only one of the two per-user locations is read by default: ~/Library/Paths on a Mac, ~/.config/paths everywhere else. Switch the other one on with --config or --lib (off a Mac, ~/.config/paths is then read ahead of ~/Library/Paths), and leave any of the three out with --no-lib, --no-config or --no-etc.

Files inside a .d directory are read in byte order, not the order ls or Finder use: upper case sorts before lower case, so 10-Zeta comes before 10-alpha, and digits are compared as characters, so 9-foo comes after 10-bar. A leading ~ in a path is expanded from HOME. Keeping one file per installed thing means uninstalling it is one rm, not a hunt through a dotfile for the bits you added a year ago.

The other variables

Same pattern, different filename. That is why it is ~/Library/Paths/paths and not ~/Library/paths — the directory holds the whole family.

VARIABLE
FILES
PATH
paths, paths.d/

manpaths, manpaths.d/

Each one is looked for in the same three places as paths, with the same defaults and switches. Typing man for something you just installed and getting the right page is a quietly excellent feeling.

07 / FAQ

Reasonable questions

Do I need a Mac?

No. It should work on any unix-like system. The Ruby version needs Ruby 2.6 or above, which is the (deprecated) system Ruby macOS ships, so anything newer is fine. If yours is older, or you would rather not depend on Ruby at all, use the Crystal build.

Ruby or Crystal?

Both. The Ruby script is the easiest thing to drop onto a machine you do not control. The Crystal build is a compiled binary, which is nicer if you want no runtime dependency at shell startup.

Will it change my PATH for me?

No, and that is deliberate. It prints a string. You assign it: PATH=$(path_helper -p).

Does it interfere with Apple's one?

Not at all. Apple's stays in /usr/libexec and is left alone. Install this anywhere you like and call it by its full path.

My terminal fills up with Ruby warnings

Recent Ruby versions are enthusiastic about warnings. Send them somewhere else: PATH=$(ruby /path/to/path_helper -p 2>/dev/null)

Can my app add to the user's PATH with this?

Yes, and please do. Write one file into the user's paths.d/ with a sensible numeric prefix, and remove that file on uninstall. No munging someone else's dotfiles.

08 / CONTRIBUTING

Bring a spec or an example

Open an issue or send an email. Pull requests are welcome; if you want a feature or have found a bug, a spec or a small example makes it much quicker to act on. A Makefile drives Docker and Podman builds and tests across several versions of both Ruby and Crystal.

# build and test everything, Ruby and Crystal
make all

# just the tests
make test-all
make test-crystal-all

# one version at a time
make test RUBY_VER=3.3
make test-crystal CRYSTAL_VER=1.14.0

# poke around inside a container
make shell RUBY_VER=3.3

# every target
make help

GitHub Actions runs the same shell test suite against both implementations on pushes and pull requests to master and dev across a matrix of Ruby and Crystal versions on Ubuntu, macOS and Alpine. Testing workflow changes locally with act before pushing saves everyone a round trip.
